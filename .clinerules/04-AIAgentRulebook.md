# AI Agent Rulebook

- Confirm Understanding: Before writing any code or text, restate the task in your own words and ask for clarification on anything ambiguous.
- Scope & Granularity: Break every request into the smallest meaningful sub-tasks. Complete and confirm each sub-task before moving on.
- Follow Style Guides: Always adhere to the project’s coding conventions (naming, formatting, folder structure) and comment standards. If no guide exists, use the official Unity C# Style Guide.
- Document Continuously: For every code change, update or create inline comments, API docs, and the project README as needed. Never let code drift from its documentation.
- Automate Tests: Write or update unit/integration tests for every new method, class, or behavior you implement. Ensure all tests pass before delivering code.
- Self-Review & QA: After generation, perform a “self-audit”:
    - Check for obvious syntax errors or missing references
    - Verify that public APIs are consistent
    - Flag any assumptions you made
- Atomic Commits: Group changes by single responsibility. Each commit (or code block you submit) should implement exactly one feature or fix.
- Error Handling & Logging: Always include robust error checks and meaningful log messages for runtime exceptions or invalid inputs.
- No Silent Failures: If you can’t complete a sub-task—because of missing info, external dependency issues, or uncertainty—halt and ask before proceeding.
- Respect Dependencies: Don’t introduce new packages or assets without explicit approval. Opt for built-in Unity APIs or already-approved libraries first.
- Performance Mindset: For any algorithmic code—physics, rendering loops, AI logic—annotate its Big-O cost, and suggest optimizations if O(n²) or worse.
- Security & Safety: Never log sensitive data. Sanitize any inputs that might come from external sources (user data, file paths, network).
- Summarize Deliverables: At the end of each task or code block, provide a brief summary of what you’ve done, what still needs review or testing, and any open questions.
- Version Awareness: Always target the project’s current Unity and .NET versions. If you reference an API, cite its exact version and documentation link.
- Fallback Handling: Do not generate fallbacks without asking the human for help. 
    - Best practices implementation is preferred over using fallbacks to deprecated methods.
    - Fallbacks may hide errors we better handle early.
